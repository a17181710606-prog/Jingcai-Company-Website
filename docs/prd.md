# 影视设备管理与展示系统 PRD

## 1. 项目概述

### 1.1 项目名称
内部优先的影视设备管理与展示系统（V1）

### 1.2 项目定位
本项目第一阶段不是完整交易闭环租赁平台，而是一个以内部运营效率为核心的设备管理与展示系统。系统同时服务两类目标：

1. **后台内部运营**：建立清晰、可追踪、可统计的设备台账与库存管理体系。
2. **前台品牌展示**：对外展示公司设备能力、服务能力、案例与 AI 项目能力，并提供联系询价入口。

### 1.3 V1 核心目标
- 设备台账清晰
- 库存状态可视化
- 出入库可追踪
- 调度效率提升
- 前台可展示公司设备与服务能力

### 1.4 V1 明确不做
- 在线支付
- 保险
- 合同自动签署
- 完整订单履约
- 复杂结算系统
- 多商户独立后台

## 2. 用户角色

### 2.1 内部角色
1. **Super Admin**
   - 拥有全量后台权限
   - 管理用户、系统配置、所有业务数据
2. **Admin / Operations**
   - 负责设备录入、编辑、状态更新、项目关联、日志查看
3. **Warehouse / Scheduler**
   - 负责出入库、状态切换、设备调度、库存查看
4. **Editor / Content Manager**
   - 负责前台展示内容、案例、服务页、AI 项目维护

### 2.2 外部角色
1. **Public Visitor**
   - 浏览公开设备目录、设备详情、服务能力、案例与 AI 项目
   - 提交联系或询价请求

## 4. 核心业务问题

### 4.1 当前典型问题
- 设备信息分散，缺乏统一编号与参数标准
- 设备状态不透明，不清楚是在库、外借、维修还是停用
- 出入库缺少统一日志，难以追溯责任与时间节点
- 项目调度依赖人工沟通，效率低
- 对外展示内容和后台真实库存脱节

### 4.2 系统需要解决的关键问题
- 让每台设备具备唯一身份与可追溯生命周期
- 让设备状态变化有记录、有责任人、有时间戳
- 让后台快速筛选、查看、录入、更新设备信息
- 让前台只展示可公开设备与内容，避免暴露内部信息

## 5. 功能需求

## 5.1 后台 V1 必须包含

### 5.1.1 登录与鉴权
- 管理员通过 `/admin/login` 登录
- 基于 Supabase Auth 实现身份认证
- 未登录用户不能访问后台路由
- 根据角色控制后台页面和操作权限

### 5.1.2 仪表盘 `/admin`
展示关键库存指标：
- 设备总数
- 可用设备数
- 使用中设备数
- 维修中设备数
- 停用设备数
- 最近出入库记录
- 即将归还/待调度设备（若已有项目关联）
- 分类维度统计

### 5.1.3 设备分类管理 `/admin/categories`
- 新增分类
- 编辑分类
- 设置父子级关系（建议支持二级）
- 控制排序
- 控制是否公开展示

### 5.1.4 所属方管理 `/admin/owners`
- 新增所属方
- 编辑所属方
- 标记所属方类型（自有 / 合作方 / 挂靠方 / 第三方）
- 记录联系人与备注

### 5.1.5 设备管理 `/admin/equipment`
- 设备列表
- 关键字段筛选（分类、状态、所属方、公开状态）
- 新建设备 `/admin/equipment/new`
- 编辑设备 `/admin/equipment/[id]`
- 维护设备编号、名称、品牌、型号、参数、标签、所属方
- 维护封面图与图集
- 设置公开展示状态

### 5.1.6 状态管理
每台设备必须具备明确库存状态，至少包括：
- available：在库可用
- reserved：已预留
- checked_out：已出库 / 使用中
- maintenance：维修中
- unavailable：不可用
- retired：停用 / 下架

要求：
- 每次状态变更必须记录日志
- 记录变更前后状态、操作人、时间、备注

### 5.1.7 出入库日志 `/admin/inventory-logs`
- 记录入库、出库、状态切换、项目关联、备注
- 支持按设备、项目、操作人、时间范围筛选
- 保留审计用途，不允许普通运营删除

### 5.1.8 项目管理 `/admin/projects`
- 创建项目
- 录入项目名称、客户、时间区间、地点、备注
- 关联设备
- 查看项目下设备使用情况

### 5.1.9 内容管理 `/admin/showcase`
- 管理服务内容、案例展示、AI 项目展示
- 控制前台是否发布

## 5.2 前台 V1 必须包含

### 5.2.1 首页 `/`
- 公司简介
- 核心服务能力摘要
- 推荐设备 / 热门设备
- 案例 / AI 项目入口
- 联系询价入口

### 5.2.2 服务页 `/services`
- 展示拍摄服务、设备支持、技术能力、执行能力

### 5.2.3 设备目录 `/equipment`
- 展示公开设备
- 支持按分类筛选
- 支持基础搜索

### 5.2.4 设备详情 `/equipment/[id]`
- 展示设备名称、编号/公开编号、图片、参数、说明、标签
- 展示是否可询价
- 不展示内部敏感信息（如采购成本、内部备注）

### 5.2.5 案例展示 `/showcase` 与 `/showcase/[slug]`
- 展示公司案例、项目亮点、相关图文内容

### 5.2.6 AI 项目展示 `/ai-projects`
- 展示公司 AI 相关项目、能力说明与代表案例

### 5.2.7 联系页 `/contact`
- 联系方式
- 表单或询价入口
- 可预留后续 CRM/邮件通知能力

## 6. 非功能需求

### 6.1 技术栈
- Next.js
- TypeScript
- Supabase（Database / Auth / Storage / RLS）
- GitHub
- Vercel

### 6.2 权限与安全
- 后台所有数据默认非公开
- 前台只读取显式标记为公开的数据
- 通过 Supabase RLS 控制数据访问
- 关键动作记录日志

### 6.3 数据追踪与审计
以下动作应尽量写入日志：
- 创建设备
- 更新设备信息
- 设备状态切换
- 设备图片变更
- 项目设备关联/解除关联
- 分类与所属方变更
- 内容发布/下线

- 结算系统

## 7. 关键数据原则

### 7.1 设备唯一标识
每台设备必须具备：
- 系统 ID
- 内部唯一编号（SKU / asset_code）
- 所属分类
- 当前状态

### 7.2 状态流转必须可追踪
- 当前状态存储于设备主表
- 每次变更写入 inventory_logs
- 必须能知道谁在什么时候进行了什么操作

### 7.3 前后台数据隔离
- `is_public = true` 的设备和展示内容才能进入前台
- 内部字段与公开字段尽量拆分或明确约束

## 8. 成功指标（V1）

### 8.1 后台运营指标
- 100% 在管设备具备唯一编号与明确状态
- 100% 设备状态变更可追踪
- 可在 3 分钟内完成单台设备新建录入
- 可在 10 秒内检索指定分类/状态设备

### 8.2 前台展示指标
- 能清晰展示设备能力、服务能力与案例能力
- 支持访客完成联系询价
- 公开内容与后台配置保持一致
